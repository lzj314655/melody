## 2. 测试分层执行

### L1: 单元测试(JUnit5 + Mockito)

**目标覆盖清单**(每条 = 1 个测试类,至少 1 用例):

| Service | 关键方法 | 必测分支 |
|---|---|---|
| `OrderServiceImpl.createOrder` | 价格计算 / 库存预扣 / 优惠券核销 / 钱包扣减 | 库存不足抛异常;钱包余额不足抛异常;同一优惠二次使用抛异常 |
| `OrderServiceImpl.cancel` | 状态合法性校验 | 已发货订单取消 → 抛 `BizException` |
| `OrderServiceImpl.confirmReceive` | 状态机 | 已取消订单确认 → 抛 |

| `WalletServiceImpl.recharge` | 幂等 | 同一请求两次提交不重复入账 |
| `WalletServiceImpl.pay` | **并发** | 余额刚好够时,两个并发请求只能一个成功 |
| `CouponServiceImpl.claim` | 限领 / 总量校验 | 同一用户领两次 → 第二抛异常 |
| `CouponServiceImpl.useCoupon` | 状态校验 | 过期券/已使用券 → 抛 |
| `RecommendServiceImpl.getPersonalRecommend` | Redis 故障降级 | 注入 Redis 异常 → 走实时 ItemCF;再异常 → 冷启动兜底 |
| `BehaviorServiceImpl.report` | 异步落库 | 调用失败不抛;3 次重试后放弃 |
| `JwtUtil.parseToken` | 过期 / 篡改 / 错签 | 三类异常 |
| `PasswordEncoder` | BCrypt 匹配 | 不同 cost factor 解码失败 |

## 3. 数据完整性自检 SQL

每次测试结束时跑一遍:

```sql
-- 1. 商品图是否还有外链
SELECT COUNT(*) FROM t_product WHERE cover_image LIKE 'http%';
-- 期望:0

-- 2. 评价是否超过订单商品数
SELECT product_id, COUNT(*) c FROM t_product_review GROUP BY product_id, order_id HAVING c > 1;
-- 期望:空集

-- 3. 钱包总账
SELECT user_id, balance FROM t_wallet_account ORDER BY balance DESC LIMIT 10;

-- 4. 订单状态分布
SELECT status, COUNT(*) FROM t_order GROUP BY status;

-- 5. 优惠券总账
SELECT coupon_id, COUNT(*) FROM t_user_coupon GROUP BY coupon_id;

-- 6. 行为埋点 24h 分布
SELECT type, COUNT(*) FROM user_behavior_log
WHERE created_at > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY type;
```
