## 2. 测试分层策略

按 **风险从高到低 × 自动化成本从低到高** 的原则,分四层:

| 层 | 范围 | 工具 | 谁来跑 | 节奏 |
|---|---|---|---|---|
| **L1 单测** | 后端 Service/Util、前端 store/util | JUnit5、Mockito(后);手写 assert 函数(前) | 开发自测 | 提交前 |
| **L2 契约 / API 测试** | 后端每个 REST 端点 | 脚本调用(JMeter / Python `requests` / Postman) | 测试 | 每个版本 |
| **L3 集成测** | 前后端联调链路 | 浏览器手工 + 关键路径脚本 | 测试 + 开发 | 每周 / 上线前 |
| **L4 UAT 验收** | 业务流端到端 | 浏览器手工 | 用户/答辩评委 | 答辩前 |

**关键决定**:
- **后端无 `src/test/`、前端无 vitest/jest**:不强行补框架,优先产出**手工/脚本型**测试用例,在文档里给到具体可执行的请求/期望。
- **MySQL / Redis 强依赖**:测试不能跑干净的容器化栈。文档里写清楚"测试前必须就位的环境"。
- **行为埋点无 schema 文档**:完全靠 `BehaviorTypeEnum` + 反查前端 `behavior.js` 的 10 处调用反推。

## 3. 全局高风险功能清单(必须重点覆盖)

> 来源:后端 120 个 java + 前端 23 个 view + 接口清单 + 既有事故(图片代理)。

| # | 模块 | 风险点 | 已在事故 | 测试重点 |
|---|---|---|---|---|
| **R1** | **JWT 安全** | 无 refresh、logout 不失效、`/api/admin/system/data-reset` 高破坏、CORS 全开 | — | 401 跳登录、admin token 越权访问前台、reset-data 不带二次确认 |
| **R2** | **订单状态机** | 状态判定散落、用字符串硬编码;下单直接落 `PENDING_SHIP` 跳支付;无幂等键 | — | 状态合法迁移、非法跳转拒绝、退款后不能再发货 |
| **R3** | **支付 / 钱包** | 无第三方回调,但**内部支付无幂等**;扣减无分布式锁;并发下可能多扣 | — | 钱包余额并发扣减、同一订单多次支付的回滚 |
| **R4** | **权限角色** | 后台细粒度权限(`product:create` 等) + ROLE 双层(`@PreAuthorize` + SecurityFilterChain) | — | OPERATOR 拿不到 SUPER_ADMIN 接口、user token 调 `/api/admin/**` 被拦 |
| **R5** | **商品图片** | Vite 代理 ↔ WebMvcConfig ↔ 本地磁盘,任一环断就全图裂;DB 残留 http URL | ✅ 上一轮已出过事故 | 9 个抽样商品都 200;DB 自检 `cover_image LIKE 'http%'` 应为 0 |
| **R6** | **行为埋点** | `fetch+keepalive` 异步上报,失败静默;v2 mock 和真实后端并行存在 | — | 列表/详情/加购/收藏/评价/结算 6 类事件至少各 1 条入库 |
| **R7** | **SQL 注入** | MyBatis-Plus Wrapper 安全,但任何 `$` 拼接都是危险 | — | 搜索框、登录名、订单 id 输入 `' OR 1=1` |
| **R8** | **并发超卖** | 钱包/积分/优惠券 是否有乐观锁 / 行锁 | — | 钱包充值 + 消费并行;用户并发领同一张券 |
| **R9** | **退款** | 无外部回调,但 `refund-approve` 路径会**扣回积分 / 退回库存**吗? | — | 退款后钱包流水方向、库存/积分一致 |
| **R10** | **公告 / 轮播接口未实现** | `SecurityConfig` 已放行,但**没有 Controller** —— 前端调用会 404 | — | 首页拉 `banner/list` 与 `announcement/list` 必须 200 |
| **R11** | **Rec 接口路径不匹配** | `/api/coupon/claim` 白名单与实际 `/api/coupon/{id}/claim` 不一致 → 走 `authenticated()` | — | 未登录用户领券被 401 还是被 200? |
| **R12** | **DB 口令硬编码 + 弱 JWT 密钥** | `******`（本机口令不入库） + 兜底密钥进 yml | — | 不算功能 bug,但答辩时若被问"安全"要能说出来 |
