### 0.3 关键技术决策与权衡

#### 决策 1：Mapper 用 H2 而非 Testcontainers

- **原因**：H2 启动快、零依赖、CI 友好；H2 + `MODE=MySQL` 兼容方言满足绝大多数 SQL 测试。
- **代价**：JSON 列需改为 TEXT（schema-test.sql 已处理），少量 MySQL 专属语法需适配（如 `ON DUPLICATE KEY UPDATE`）。
- **替代方案**：testcontainers + mysql:8 — 更真实但需 Docker，启动慢。

#### 决策 2：Controller 用 standaloneSetup 而非 @WebMvcTest

- **原因**：项目启动类含 `@MapperScan("com.melody.mapper")`，`@WebMvcTest` 仍会触发 mapper bean 创建 → `MapperFactoryBean` init 失败（无 SqlSessionFactory）。
- **代价**：失去 Spring Security Filter chain 验证，需用 `Mockito.mockStatic(SecurityUtils.class)` 手动模拟登录。
- **替代方案**：在 `@WebMvcTest` 加 `excludeFilters = @ComponentScan.Filter(type = ASSIGNABLE_TYPE, classes = Mapper.class)` — 工作量大、容易遗漏。

#### 决策 3：纯算法走 JUnit，Service/Mapper 走 Mockito + Spring

- **ItemCFEngine** 纯 Java 算法，不依赖任何框架，单测无 Spring 启动开销（15 个测试 < 0.02s）。
- **Service** 用 Mockito mock 所有 Mapper / 其他 Service，单测不连数据库（181 个测试 < 0.3s）。
- **Mapper** 必须真实跑 SQL，故用 `@SpringBootTest + H2`（61 个测试 < 10s，含 Spring 启动开销）。

### 0.4 关键 Bug / 坑位（解决记录）

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | `data-test.sql` 空文件导致 Spring `IllegalArgumentException: 'script' must not be null` | 删除文件，并去掉 yml 中 `data-locations` |

| 7 | `Mockito.mockStatic(SecurityUtils.class)` 后没 close 导致污染其他测试 | `@AfterEach` 调 `mocked.close()` |
| 8 | `BizException.getMsg()` 不存在（Lombok @Getter 生成的 `getMessage()`） | 全部用 `getMessage()` |
| 9 | `JSON 列 → TEXT` H2 不识别 `JSON` 类型 | schema-test.sql 全部改 TEXT，JacksonTypeHandler 仍能解析 |

| 13 | `application.yml` `logic-delete-field: deleted` 触发 MyBatis-Plus 全局拦截 | 实际 entity 无 deleted 字段，测试不受影响 |
| 14 | `selectBatchIds(List.of(...))` 返回 immutable List → 代码 `removeIf` 抛 `UnsupportedOperationException` | mock 返回 `new ArrayList<>(List.of(...))` |
| 15 | 错误包路径 `com.melody.exception.GlobalExceptionHandler` 实际在 `com.melody.config` | 批量 sed 修复所有 controller 测试 import |

#### 关键技巧：事务同步

OrderServiceImpl.create 用 `TransactionSynchronizationManager.registerSynchronization(...)` 在事务提交后广播新订单。单元测试时没有事务上下文，需要在 `@BeforeEach` 手动初始化：

```java
@BeforeEach
void initTx() {
    if (!TransactionSynchronizationManager.isSynchronizationActive()) {
        TransactionSynchronizationManager.initSynchronization();
    }
}

@AfterEach
void clearTx() {
    if (TransactionSynchronizationManager.isSynchronizationActive()) {
        TransactionSynchronizationManager.clear();
    }
}
```

### 3.5 Controller 测试（65 用例）

**模式**：`MockMvc.standaloneSetup(controller)` + `@MockBean` Service/Mapper 依赖

**为什么不用 @WebMvcTest**：

`@WebMvcTest` 默认会扫描启动类的 `@MapperScan("com.melody.mapper")`，导致所有 `XxxMapper` 被实例化为 `MapperFactoryBean`，但 `@WebMvcTest` 不加载 MyBatis-Plus auto config（无 SqlSessionFactory bean），所有 mapper init 失败 → ApplicationContext 加载崩溃。

`standaloneSetup` 完全不启动 Spring 容器，直接 `new Controller(...)` 注入 mock 依赖 → 干净、零冲突。

**额外配置**：启用 Bean Validation + Spring MVC 默认异常处理器：

```java
LocalValidatorFactoryBean validator = new LocalValidatorFactoryBean();
validator.afterPropertiesSet();

ResponseEntityExceptionHandler defaultHandler = new ResponseEntityExceptionHandler() {};

mockMvc = MockMvcBuilders.standaloneSetup(controller)
        .setControllerAdvice(new GlobalExceptionHandler(), defaultHandler)
        .setValidator(validator)
        .build();
```

**Static 方法 mock**：`SecurityUtils.currentId()` 是 static，用 `Mockito.mockStatic`：

```java
try (MockedStatic<SecurityUtils> mocked = Mockito.mockStatic(SecurityUtils.class)) {
    mocked.when(SecurityUtils::currentId).thenReturn(1L);
    // ...
}
```
