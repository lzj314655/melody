# 麦乐迪零食购物商场系统 — 选题分析

> 视角：产品经理 | 结论先行

---

## 一、结论摘要

**这个选题能毕业，但平庸。** SpringBoot + Vue 商城是计算机毕设最经典的"烂大街"模板，2020 年后几乎每届都有学长做过。直接按 CRUD 商城做，答辩时被老师追"创新点"会非常被动。

**核心风险**有 3 个，按严重程度排序：
1. **品牌侵权风险**：麦乐迪（Maledi / 麦乐迪）是真实存在的零食品牌或餐厅品牌，使用真实品牌名做毕设存在侵权与学术合规双重问题——答辩时评委可能直接质疑"你是否侵权？"
2. **同质化严重**：B站、CSDN、GitHub 上"基于SpringBoot+Vue的商城"成品项目超 5000 个，差异化不足
3. **技术价值低**：CRUD + 支付 SDK 接入几乎不体现工程能力，简历竞争力弱

**唯一可救方案**：把"零食垂直电商"作为差异化标签,叠加至少 1 个创新功能（推荐算法 / 数据大屏 / 会员成长体系 / 秒杀系统),避免落入"换皮的淘宝"模板。

## 二、产品定位

### 2.1 目标用户

| 角色 | 画像 | 核心场景 |
|------|------|----------|
| 普通用户 | 18-35 零食爱好者 | 浏览、加购、下单 |
| 会员用户 | 复购客户 | 看积分、领优惠券、参与活动 |
| 商家/客服 | 店主/售后 | 回复工单、处理退款 |
| 系统管理员 | 店主本人或运营 | 商品上下架、订单审核、数据看板 |

### 2.2 业务定位
- **垂直零食电商**，不是综合商城
- 核心价值：**"一站式购齐零食"**（分类齐全、组合套餐、试吃装）
- 与淘宝/京东的差异：垂直深度 + 套餐组合 + 试吃装 + 场景化营销

### 2.3 产品愿景
一句话：**"让用户像逛零食店一样逛线上商城"** —— 强氛围感、零食分类清晰、套餐推荐贴心。

## 三、功能需求拆解

### 3.1 前台（用户端）

```
首页
├── 轮播图 / 公告
├── 分类导航（按零食类型：坚果、糖果、膨化、饮料、零食礼包）
├── 热门推荐 / 新品上架
├── 限时活动入口
└── 个性化推荐（差异化点）

商品模块
├── 商品列表（筛选：分类、价格、销量、评分）
├── 商品详情（图文、规格、评价）
├── 加购 / 立即购买
└── 收藏 / 分享

购物车
├── 商品列表 + 数量调整
├── 失效商品提醒
├── 价格合计 + 优惠计算
└── 结算入口

订单模块
├── 提交订单（地址、支付方式、优惠券）
├── 支付（沙箱支付宝/微信 或 二维码截图）
├── 订单状态跟踪（待付款、待发货、待收货、已完成、售后）
└── 申请退款

用户中心
├── 个人信息 / 收货地址
├── 我的订单 / 收藏 / 优惠券
├── 会员等级 / 积分
└── 消息通知
```

### 3.2 后台（管理端）

```
数据看板（差异化亮点）
├── 销售统计（GMV、订单数、客单价）
├── 用户增长趋势
├── 商品销售 TOP10
└── 分类销售占比饼图

商品管理
├── 商品 CRUD + 上下架
├── 分类管理（多级分类）
├── 库存管理（含预警）
└── 评论管理

订单管理
├── 订单列表 + 状态筛选
├── 订单详情 / 发货 / 退款审核
└── 导出 Excel

营销管理（加分项）
├── 优惠券（满减、折扣、限时）
├── 限时活动（秒杀/拼团）
└── 满减规则

用户管理
├── 用户列表（黑名单、标签）
├── 会员等级设置
└── 客服工单

系统管理
├── 管理员账号 / 角色 / 权限
├── 轮播图 / 公告
├── 操作日志
└── 数据字典
```

### 3.3 功能优先级

| 优先级 | 模块 | 是否必须 |
|--------|------|----------|
| P0 | 注册登录、商品 CRUD、购物车、订单 CRUD、支付 | 必须 |
| P1 | 后台管理、分类管理、地址管理、收藏、搜索 | 必须 |
| P2 | 优惠券、积分、数据看板 | 加分 |
| P3 | 个性化推荐、秒杀、客服 IM | 差异化亮点 |

## 四、技术选型建议

### 4.1 推荐技术栈（带理由）

```
前端
├── Vue 3 + Composition API（推荐，趋势）
├── 或 Vue 2 + Element UI（稳妥，资料多）
├── Element Plus / Element UI（主流管理后台组件库）
├── Axios（HTTP）
├── Vue Router + Pinia/Vuex（路由 + 状态）
└── ECharts（数据看板图表）

后端
├── Spring Boot 2.7 / 3.x
├── Spring Security + JWT（认证）
├── MyBatis-Plus（ORM，简化 CRUD）
├── MySQL 8.0（数据库）
├── Redis（缓存、Session、限流）
├── Swagger / Knife4j（接口文档）
├── Lombok（简化代码）
└── Maven（构建）

部署 & 工具
├── Nginx（前端静态资源）
├── 七牛云/本地（图片存储）
├── Git（版本管理）
└── Postman / Apifox（接口测试）
```

### 4.2 技术选型不推荐

- ❌ Spring Cloud 全家桶：单机项目用微服务是过度设计
- ❌ GraphQL：毕设场景下不上不下，调试难度高
- ❌ WebSocket 全双工通信：除非做 IM 或实时通知，否则用轮询即可
- ❌ MongoDB：和大多数毕设评审老师知识栈不一致，容易被追问

## 五、可行性分析

### 5.1 技术可行性 ✅
SpringBoot + Vue 是高校教学最主流的技术组合，资料、教程、博客、视频极其丰富，开发过程中遇到的问题几乎都可以搜到解决方案。

### 5.2 经济可行性 ✅
- 软件成本：0（全部开源）
- 服务器成本：本地运行即可，演示时用腾讯云学生机或本地演示
- 数据成本：用 Mock 数据或爬虫爬零食数据填充

### 5.3 时间可行性 ✅
工作量评估（单人开发）：

| 阶段 | 内容 | 时间 |
|------|------|------|
| 第 1-2 周 | 需求分析、技术选型、原型设计 | 2 周 |
| 第 3-6 周 | 后端搭建、数据库设计、核心接口 | 4 周 |
| 第 7-10 周 | 后台管理端开发 | 4 周 |
| 第 11-14 周 | 前台用户端开发 | 4 周 |
| 第 15-16 周 | 数据看板 / 推荐算法（差异化） | 2 周 |
| 第 17-18 周 | 测试、Bug 修复 | 2 周 |
| 第 19-20 周 | 部署、写论文、准备答辩 | 2 周 |

**总计：20 周（5 个月）**，正常节奏可完成。

### 5.4 法律与合规可行性 ⚠️
**这是最被忽视、但最严重的问题**：
- "麦乐迪"是真有品牌（搜索确认：是"麦乐迪餐饮"等真实商业主体）
- 实际商业使用的品牌名作为毕设项目名可能构成商业混淆
- 答辩时部分高校答辩委员会会要求**避免使用未授权的商业品牌名**
- 论文查重系统也会标记"麦乐迪"为商业实体

**建议**：使用 **`蜜语零食商城` / `趣食客` / `嚼趣 Shop` / `百味坊`** 等自造品牌名。

## 六、核心差异化策略（决定评分上限）

### 差异化方向选择

#### 方向 A：个性化推荐（推荐，难度中等）
- 基于用户浏览、购买、加购历史的协同过滤
- 商品详情页"猜你喜欢"
- 首页"为你推荐"栏目
- 实现：Apache Mahout / 简易 User-CF 算法
- **工作量**：+1-2 周
- **答辩亮点**：有明确的算法与数据流

#### 方向 B：数据可视化大屏（推荐，难度低）
- 后台 ECharts 看板：GMV、订单趋势、用户分布、销售排行
- 食品行业垂直分析维度：口味分布、场景分布（聚会/休闲/送礼）
- **工作量**：+1 周
- **答辩亮点**：效果直观、不容易出错

#### 方向 C：会员成长体系（推荐，难度低）
- 等级 + 积分 + 勋章 + 任务 + 优惠券发放
- 增加用户粘性，体现产品思维
- **工作量**：+1 周
- **答辩亮点**：能讲清楚运营逻辑

#### 方向 D：秒杀系统（不推荐，难度高）
- 需要处理高并发、库存超卖、限流、消息队列
- 毕设单机演示容易出 Bug，调试成本高
- **不建议**，除非你对并发有把握

### 我的建议
**方向 A + B 组合**：推荐算法 + 数据大屏，把"算法"和"工程实践"两个维度都覆盖。**这是毕设最高性价比搭配**。

如果能力有限，**B + C** 也足够应付答辩。

## 七、工作量风险与避坑指南

### 7.1 高风险点

| 风险 | 后果 | 应对 |
|------|------|------|
| 支付集成 | 沙箱调试难，环境配置麻烦 | 用**支付截图演示**+**模拟支付回调**，90% 毕设这样做 |
| 富文本编辑器 | 商品描述编辑需求 | 用 wangEditor / TinyMCE |
| 文件上传 | 图片上传路径、跨域 | Nginx 静态映射或本地存相对路径 |
| 部署上线 | 环境变量、JDK 版本、依赖冲突 | Docker Compose 一键部署是加分项 |
| 推荐算法 | 数据稀疏、冷启动 | 准备 Mock 数据演示 |
| 数据初始化 | 演示数据准备 | 写 SQL 脚本批量插入测试数据 |

### 7.2 容易被怼的点（提前准备应对）

1. **"你这个项目有什么创新？"** → 用差异化方向（推荐/大屏/会员体系）回答
2. **"为什么不用 XX 技术？"** → 能讲清楚取舍（Spring Cloud 过度、GraphQL 调试难等）
3. **"性能如何保证？"** → Redis 缓存热点、Nginx 静态资源、SQL 索引
4. **"安全性如何？"** → JWT、BCrypt 密码、XSS 过滤、SQL 注入（MyBatis-Plus 防）
5. **"上线了吗？"** → 演示环境 + 部署文档，先做到"能跑起来"即可

## 八、最终决策建议

### 我的结论

> **选题通过。** 但请务必做以下调整，否则答辩分数上限会被锁死在 75 分左右（中等水平）。

### 必须做的 3 件事

1. **改名**：避免使用"麦乐迪"等真实商业品牌名，改用自造品牌（如"嚼趣零食")
2. **加 1-2 个差异化点**：推荐算法 + 数据大屏是最优组合
3. **部署上线**：哪怕只是部署到一台云服务器或本机 Nginx 演示，也是巨大加分

### 可选做的 2 件事

4. **准备答辩演示脚本**：提前录 3 分钟演示视频（避免现场翻车）
5. **写技术博客**：CSDN/掘金记录开发过程，面试时能用上

### 不需要做的事

- ❌ 微服务架构（过度设计）
- ❌ Docker Swarm / K8s（毕设用不上）
- ❌ 大数据 / 机器学习（不是毕设主要内容）
